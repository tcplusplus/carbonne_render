# T28: frontend naar TypeScript met Vite

**Oordeel: gehaald.** De interface is nu strikt getypte TypeScript (Vite, geen framework, geen herontwerp). De
types komen uit het Pydantic-schema van de backend, three.js komt uit npm, en `uv run carbonne-app start` volstaat
omdat de gebouwde `web/dist/` in git staat. De bestaande browser- en node-tests (T10, T16, T20, T26, T27) draaien
ongewijzigd in hun eisen, alleen met nieuwe paden.

## Starten en bouwen
- Gebruiken: `uv run carbonne-app start` (geen Node, geen internet nodig).
- Bouwen na een wijziging in `web/src/`: `npm install` (eenmalig) en `npm run build`; daarna `web/dist/` committen.
- Ontwikkelen met herladen: `npm run dev`. Alles staat in `docs/gebruik.md`.

## Wat is er veranderd
- `web/js/*.js` is `web/src/*.ts` (zelfde modules en namen). `web/vendor/three` is weg; three.js zit in de bundel.
- `web/src/types/config.ts` en `verf.ts` zijn gegenereerd uit het schema (`npm run types`); `api.ts` is met de hand
  geschreven voor de antwoorden van de server.
- De backend serveert `web/dist/` (`src/carbonne/server/app.py`).
- Nieuwe devDependencies, zoals goedgekeurd: vite, typescript, three, @types/three, json-schema-to-typescript.

## Bewijs
`npm run typecheck` (tsc --noEmit): geen fouten.

Een bewust verkeerde configwaarde, `const a: WoodSlice = { type: "wood", count: "veel" }`, wordt afgekeurd:
```
fout.ts(2,45): error TS2322: Type 'string' is not assignable to type 'number'.
```
`tests/test_t28.py` (5 tests) controleert: schemabestanden lopen niet achter op de backend, gegenereerde types horen
bij het schema, `tsc --noEmit` is schoon, drie verkeerde waarden (tekst als aantal, onbekend verftype, onbekend
veld) compileren niet terwijl een juiste wel compileert, en een verse build geeft exact dezelfde bestanden als
`web/dist/`.

Tests T10, T16, T20, T26, T27 en T28 samen: 58 geslaagd. T10 draait de hele UI in Chrome met een echte server, inclusief
een nieuwe controle dat index en bundel worden geserveerd zonder externe adressen.

Beelden: de werkende pagina na twee echte HQ-renders en een A/B-vergelijking (`docs/evidence/img/T28-ui.png`,
geen fouten in de browserconsole) en de preview (`docs/evidence/img/T28-preview.png`).

Getallen: bundel ca. 629 kB js (165 kB gzip) plus 10 kB css; `web/dist/` is 680 kB; 2085 regels TypeScript.

## Niet getest
- `npm run dev` (ontwikkelserver met doorsturen naar de backend) is niet in een browser doorlopen.
- Andere browsers dan Chrome en andere Node-versies dan v24.
- Offline gedrag is afgeleid uit het ontbreken van externe adressen in index en bundel, niet met een afgesneden netwerk.

## Beperkingen
- De UI-config wijkt op enkele punten af van het schema (kleur als hex-tekst, weggelaten standaardvelden); dat is in
  het type `Cfg` apart vastgelegd en niet volledig schema-afgeleid.
- Een build vraagt Node en `uv` samen (de types worden uit Python gehaald).
- Vite waarschuwt voor een grote bundel (three.js); bewust genegeerd.
- Oudere evidence-bestanden (T10, T16, T20, T27) noemen nog de paden `web/js/*.js`; dat is historie.
