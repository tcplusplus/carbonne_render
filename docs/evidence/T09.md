# T09 - Webbackend: bewijs

**Oordeel: gehaald.** De FastAPI-app draait lokaal (`uv run carbonne-app start`), levert schema, presets, geometrie en
1k-HDRI's, start renders (een tegelijk, met wachtrij), streamt voortgang via WebSocket, geeft PNG en EXR terug,
annuleert, bewaart configs en haalt een herhaalde render uit de cache. 12 API-tests groen (nep-renderer, plus een echte render
van 64x48); volledige suite 111 groen, 4 overgeslagen.

## Zichtbare stap (echte curl/WebSocket-sessie, 160x90, 64 spp, scene woonkamer/schuin30)
```
GET  /api/schema, /api/presets            -> 200 (JSON-schema; 5 omgevingen, camera's, RAL-lijst)
GET  /api/hdri/woonkamer                  -> 200, 2 097 202 bytes (1024x512 RGBE)
POST /api/render {config, opties}         -> 202 {"id": "38811c9ad8f9", "status": "wachtend"}
WS   /api/render/38811c9ad8f9             -> bezig v1; pass 1 (16 spp, 0.34 s); pass 3 (48 spp); klaar v6:
                                              pass 4, 64 spp, ruis 0.110, reden max_spp
GET  .../result.png -> 200, 32 112 bytes   GET .../result.exr -> 200, 172 235 bytes
POST /api/render (zelfde aanvraag)        -> klaar, reden "cache", uit_cache true, tijd 0.0 s
```
Beeld: `docs/evidence/img/T09-render.png` (gezien: rood gelakt tafeltje met inhoud op parket; 160x90 is bewust klein).

## Ontwerp
- `server/jobs.py`: een werkthread haalt jobs uit een rij; statussen wachtend, bezig, klaar, fout, geannuleerd.
  Annuleren van een wachtende job slaat hem over, van een lopende job zet het de `annuleer`-event van `render()`.
- WebSocket pollt de jobversie elke 0,1 s en stuurt een momentopname (met tussenbeeld als base64-PNG); wie de
  verbinding sluit annuleert niets.
- Cache: `render()` zelf (hash op config + opties + code); de server forceert zijn eigen `cache_map`.
- `POST /api/geometrie` geeft de cilindervlakken en de inhoud (dezelfde `plaats_alles`) zodat three.js nooit een eigen waarheid heeft.
- Confignamen: alleen `A-Za-z0-9_-` (pad-traversal geweigerd, getest).

## Niet getest / beperkingen
- Geen bevestiging op eindformaat (1280x720, ~12 min): de server wijzigt de pijplijn niet en de tijd is die van T08.
- Geen authenticatie; alleen 127.0.0.1.
- Poort 8000 was op deze machine door een ander proces bezet; de sessie draaide op `--port 8011`.
- Jobs en tussenbeelden blijven in het geheugen tot de server stopt; EXR's van niet-gecachte resultaten staan in `out/server/`.
- Een HQ-render blokkeert alle CPU-threads; preview-renders (`opties.preview`) wachten dus ook in dezelfde rij.
