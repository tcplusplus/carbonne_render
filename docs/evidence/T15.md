# T15 — API voor herkomst en wat-als-reeksen: bewijs

## Oordeel: gehaald

De server kan nu (1) een render met herkomst starten, (2) daarvan per punt of gebied de herkomst van de kleur
geven zonder opnieuw te renderen, en (3) wat-als-reeksen starten, volgen via een WebSocket, annuleren en
ophalen (JSON plus beelden). Reeksen en renders delen één wachtrij en één werkthread. API-tests (nep-renderer met
55 herkomstkanalen): 11 stuks groen, waarvan één met een echte render met herkomst op 64x48; verder de
curl-sessie hieronder tegen de echte server.

## Zichtbare stap: curl-sessie tegen de echte server

Server: `CARBONNE_CACHE=... uv run carbonne-app start --port 8021`. Config: 4 cm blok, rode matte zijverf, zwarte
plaat met 1 mm spleet, omgeving studio, camera schuin30, 160x90 pixels.

## Wat de API doet

| eindpunt | doel |
|---|---|
| `POST /api/render` met `herkomst: true` | herkomst-integrator, ruwe kanalen bewaard |
| `GET /api/render/{id}/herkomst?x&y&r` of `?x0&y0&x1&y1` | JSON: `categorieen` (aandeel, `hex`, `hex_per_pad`, Lab, rgb), `hex`/`lab` totaal, `kerngetallen`, `n_pixels`; 409 zonder herkomst of als de render nog loopt, 422 bij een ongeldig gebied |
| `GET /api/render/{id}/herkomst.npz` | ruw: `beeld` (h, w, 55) en `kanaalnamen` |
| `GET /api/reeks/parameters` | toegestane parameterpaden met type, omschrijving, voorbeeldwaarden, min/max |
| `POST /api/reeks` | pad en alle waarden worden vooraf gevalideerd (422 met uitleg, geen job); 202 + id |
| `GET /api/reeks/{id}` | status, voortgang, de T14-JSON en de URL's van de deelbeelden |
| `WS /api/reeks/{id}` | momentopname bij elke wijziging: `voortgang {klaar, van, label}`, sluit bij klaar/fout/geannuleerd |
| `DELETE /api/reeks/{id}` | annuleren (wachtend: direct; lopend: tussen twee renders; klare metingen blijven) |
| `GET /api/reeks/{id}/beeld/{n}.png`, `contact.png`, `grafiek.png` | beelden |

## Tests

`uv run pytest tests/test_t15.py -q`: herkomst voor punt en gebied (aandelen tellen op tot 100 %, hex en Lab aanwezig,
npz-vorm), foutgevallen (409/422/404), herkomst bij een nog lopende render, levenscyclus van een reeks met
WebSocket, JSON en alle beelden, reeks in de wachtrij achter een render en annuleren (wachtend, lopend, halverwege met
gedeeltelijk resultaat), ongeldige aanvragen, een fout in de job (gebied buiten het beeld), de parameterlijst (elk
voorbeeld komt door `zet_pad`) en een echte render met herkomst (64x48, 32 spp).

## Niet getest / beperkingen

- Reeksresultaten staan in het geheugen en de `.npz` in `out/server/`; na een herstart zijn de reeks-ID's weg (de
  renders zelf staan wel in de cache). Er is geen opruiming van oude jobs.
- Een lopende render of reeks stopt pas tussen twee passes of twee renders.
- Of een voorbeeldwaarde zinvol is voor de huidige config (bv. `zijkant.color` bij een kale zijkant) wordt niet
  vooraf bekeken; een ongeldige combinatie geeft wel 422 bij het starten.
- De WebSocket van reeksen is alleen via de testclient geprobeerd, niet met een echte browser; de frontend (T16)
  gebruikt hem nog niet.
